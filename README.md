# HTTP-анализ и отладка запросов с Fiddler

Учебный QA-проект: изучаю, как приложения общаются с сервером по HTTP, и учусь перехватывать, анализировать и изменять запросы с помощью **Fiddler**.

**Статус:** все 5 сценариев выполнены.

## Цель проекта

- Научиться читать HTTP-запросы и ответы: метод, заголовки, тело, код, время.
- Освоить инструменты Fiddler Everywhere: HTTP Inspector, Composer, правила (точка останова и подмена ответа), вкладка Overview с таймингами.
- Оформить результаты как тестовые сценарии с шагами, ожидаемым и фактическим результатом.

## Объект тестирования

Открытые учебные API, для которых не нужна регистрация и ключи:

- [JSONPlaceholder](https://jsonplaceholder.typicode.com) — посты, комментарии, пользователи (CRUD-запросы).

## Инструменты

- Fiddler Everywhere (перехват и изменение трафика)
- Браузер (для отправки запросов и просмотра ответов)

## Сценарии

| № | Сценарий | Инструмент Fiddler | Статус |
|---|---|---|---|
| 01 | GET: получить пост и разобрать запрос/ответ | HTTP Inspector | Выполнен |
| 02 | POST: создать пост через Composer | Composer | Выполнен |
| 03 | Изменить запрос на лету (неверный ID) | Rules → Set Request Breakpoint | Выполнен |
| 04 | Подмена ответа сервера (500, пустой список) | AutoResponder (в Fiddler Everywhere: Rules → Return File) | Выполнен |
| 05 | Анализ времени ответа | Overview (Timings, Sizes) | Выполнен |

Сценарий 05 построен на замерах, снятых в сценариях 01–03. Выводы по всем сценариям собраны в [findings.md](findings.md).

## Как воспроизвести

1. Установить и запустить Fiddler.
2. Открыть в браузере `https://jsonplaceholder.typicode.com/posts/1`.
3. Найти запрос в списке сессий Fiddler и открыть вкладку HTTP Inspector.
4. Дальше следовать шагам из нужного файла в папке `scenarios/`.

## Безопасность

Файлы сессий Fiddler (`.saz`) и HAR-файлы не публикуются: в них могут быть заголовки авторизации и cookies. Скриншоты проверяются перед загрузкой.
